# [LTR] 교차리뷰 (codex-gpt-6.2-sol)

## 요약

`95242ab`은 세 CLI에 로컬 번역기를 연결하고, 번역 호출당 서버 하나를 재사용합니다. 혼합 모드와 FKS의 기본값도 계획을 따릅니다. 다만 **로컬 번역 요청이 환경 프록시로 전달될 수 있고, 서버가 응답 도중 종료되면 이미 끝난 음성 인식 결과도 저장되지 않을 수 있습니다.** 두 문제는 배포 전에 수정하는 편이 좋겠습니다.

| 계획 항목 | 상태 | 구현 및 자체 검증 |
| --- | --- | --- |
| LTR-Q1 기본 모델과 `LTR_MODEL` | 구현 | 지정한 Gemma GGUF와 사용자 모델 경로를 지원합니다. 캐시 미스가 있을 때만 모델을 준비합니다. 다운로드 파일 검증과 같은 이름의 모델 간 캐시 분리에 문제가 있습니다. |
| LTR-Q2 기본 번역기 | 구현 | 혼합 모드와 Finder 빠른 동작은 `local`을 사용하고, FKS는 `FKS_TRANSLATOR` 또는 `claude`를 유지합니다. 혼합 모드 기본값을 확인하는 assert가 있습니다. |
| LTR-M1 서버 실행·정리 | 부분 충족 | 가짜 서버가 시작되고 정상 종료되는 경로, 조기 종료 시 오류, 잘못된 번역 응답 이후 프로세스 정리를 검사합니다. 첫 헬스체크에서 로딩 상태를 반환하도록 제어하지 않아 대기 동작을 독립적으로 검증하지 못합니다. 조기 실패 시간, 헬스체크 타임아웃, Ctrl+C, 강제 종료 경로도 검증하지 않습니다. |
| LTR-M2 요청·검증·캐시 | 기본 기준 충족 | 배치 키 순서, `required`, `minLength`, 추가 키 금지, 키 누락 응답의 3회 재시도, 캐시 재사용을 검사합니다. 모델 파일명은 `cache_engine()`의 결과만 확인하며, 모델 변경 후 실제 캐시 미스가 발생하는지는 검사하지 않습니다. |
| LTR-M3 CLI 연결 | 부분 충족 | macOS·Linux·FKS에서 `--translator local` 파싱을 파일 쓰기 없이 직접 확인했습니다. 새 테스트는 macOS 파싱과 실행 파일 조회를 검사합니다. 실행 파일이 없는 경우와 일반 번역 오류 시 원문을 유지하는 경우는 개별적으로 검사하지만, 누락 상황에서 실제로 원문 SRT를 저장하고 종료 코드 1을 반환하는 흐름은 검사하지 않습니다. Linux 설치 안내도 빠져 있습니다. |
| LTR-M4 실제 영화 | 기록상 부분 충족 | 구현 노트에 전체 실행 7.4분과 번역 약 10초가 기록돼 있습니다. 키 매핑 오류 수정 후에는 같은 22줄을 11.6초에 다시 검증했습니다. 수정된 커밋으로 전체 영화를 재실행한 기록은 없습니다. |

`--log-disable`을 빼고 실패 로그 끝부분을 남긴 이유는 타당합니다. 배치 입력 순서를 스키마에 유지한 수정도 실제로 관찰한 키 매핑 오류를 해결하며 최종 계획에 명시돼 있습니다. 구현 노트의 ‘순서 언급 없음’은 수정 전 계획을 설명하는 문구로 읽힙니다. 캐시 미스에서만 서버를 띄우는 변경도 불필요한 다운로드와 로딩을 줄입니다. macOS 설치 확인은 계획의 `ensure_dependencies()` 대신 `main()`에 있지만, 혼합 모드와 `local` 조건을 유지하므로 기능상 영향은 없습니다.

## 지적사항

### LTR-R1 로컬 번역 요청이 환경 프록시를 경유합니다

- **분류** `확실한 문제`
- **심각도** 높음
- **위치** `make_foreign_subtitle.py:139`, `make_foreign_subtitle.py:163`
- **내용** 두 요청 모두 `urllib.request.urlopen()`의 기본 프록시 설정을 사용합니다. `http_proxy`가 설정돼 있고 `no_proxy`에 `127.0.0.1`이 빠진 환경에서는 헬스체크가 외부 프록시로 향합니다. 프록시가 헬스체크에 HTTP 200을 반환하면 번역 대상과 주변 대사가 포함된 POST도 프록시로 전달됩니다. 환경 변수만 바꾼 검사로 loopback 주소에도 프록시가 적용되는 것을 확인했습니다.
- **제안** `ProxyHandler({})`를 사용하는 전용 opener를 두고 헬스체크와 번역 요청에 공통으로 사용하세요. 로컬 주소에 대한 HTTP 리다이렉트도 거부하세요.

### LTR-R2 HTTP 응답이 중간에 끊기면 원문 자막 저장도 건너뜁니다

- **분류** `확실한 문제`
- **심각도** 높음
- **위치** `make_foreign_subtitle.py:165`, `mixed_subtitle.py:151`, `make_subtitle.py:305`
- **내용** 서버가 응답 헤더를 보낸 뒤 메모리 부족 등으로 종료되면 `res.read()`에서 `http.client.IncompleteRead`가 발생할 수 있습니다. 이 예외는 HTTP 요청 처리와 혼합 모드의 예외 처리 양쪽을 통과합니다. 이미 음성 인식이 끝났어도 자막 저장 단계에 도달하지 못합니다. `read()`에 해당 예외를 주입해 전파를 확인했습니다.
- **제안** HTTP 경계에서 `http.client.HTTPException`을 `RuntimeError`로 변환하고, 응답 본문이 중간에 끊겼을 때 원문 SRT와 실패 종료 코드가 모두 남는지 검사하세요.

### LTR-R3 HTTP 200만으로 번역 서버가 준비됐다고 판단합니다

- **분류** `확실한 문제`
- **심각도** 중간
- **위치** `make_foreign_subtitle.py:120`, `make_foreign_subtitle.py:132`
- **내용** 포트를 확인한 소켓을 닫은 뒤 자식 프로세스를 실행합니다. 그사이에 다른 로컬 프로세스가 같은 포트를 잡고 `/health`에 HTTP 200을 반환하면, 시작한 자식이 아직 살아 있는 동안 그 응답을 정상 기동으로 받아들일 수 있습니다. 첫 배치가 다른 프로세스로 향할 수 있으며, 계획에서 요구한 `status: ok` 검증도 빠져 있습니다.
- **제안** 헬스 응답 JSON의 `status == "ok"`와 응답 직후 자식 생존 여부를 확인하고, 포트 바인드 실패는 새 포트로 재시도하세요. 가짜 서버에 `503 → 200`과 `200 + 비정상 본문`을 추가해 두 경로를 검증하세요.

### LTR-R4 모델 다운로드가 동시 실행과 손상된 캐시를 처리하지 못합니다

- **분류** `확실한 문제`
- **심각도** 중간
- **위치** `make_foreign_subtitle.py:107`, `make_subtitle.py:108`
- **내용** 모델이 없는 상태에서 영상 두 편을 별도 작업으로 시작하면 두 `curl`이 같은 `.part` 파일을 씁니다. 한 작업이 파일을 최종 이름으로 바꾼 후에도 다른 작업이 같은 파일에 계속 쓸 수 있고, 두 번째 작업은 `rename()`에서 실패할 수 있습니다. 기존 최종 파일이나 다운로드 결과의 무결성도 검증하지 않아 1KB를 넘는 손상 파일이 남으면 재실행마다 재사용합니다. 네트워크가 멈췄을 때 `curl`에 연결 제한이나 저속 전송 제한도 없습니다.
- **제안** 다운로드마다 고유한 임시 파일을 사용하고, 고정한 모델 버전의 SHA-256을 확인한 뒤 원자적으로 교체하세요. 캐시된 기본 모델도 무결성 확인에 실패하면 다시 받도록 하고, 전송이 멈추면 실패를 반환하도록 `curl` 제한을 설정하세요.

### LTR-R5 이름이 같은 다른 모델이 이전 번역을 재사용합니다

- **분류** `확실한 문제`
- **심각도** 중간
- **위치** `make_foreign_subtitle.py:94`, `make_foreign_subtitle.py:590`, `make_foreign_subtitle.py:614`
- **내용** `/a/model.gguf`와 `/b/model.gguf`는 모두 `local:model.gguf`가 됩니다. 두 경로를 차례로 지정해 같은 영상을 번역하면 두 번째 모델을 로드하지 않고 첫 번째 모델의 캐시를 사용할 수 있습니다. 파일을 같은 경로에서 교체할 때도 동일합니다. 예시 경로 두 개가 같은 키를 만드는 것을 확인했습니다.
- **제안** 사용자 모델은 정규화한 경로와 파일 메타데이터를 캐시 키에 넣고, 기본 모델은 고정한 버전이나 다이제스트로 구분하세요. 같은 파일명의 다른 모델을 지정한 뒤 실제 재번역이 일어나는지 검사하세요.

### LTR-R6 모델 문맥 한도를 넘는 배치를 줄일 방법이 없습니다

- **분류** `결정 필요`
- **심각도** 중간
- **위치** `make_foreign_subtitle.py:47`, `make_foreign_subtitle.py:128`, `make_foreign_subtitle.py:582`
- **내용** 서버 문맥은 8,192토큰인데, 혼합 모드는 번역 대상 100줄에 각 대상의 앞뒤 5줄을 붙입니다. 대상이 충분히 떨어져 있으면 한 요청에 원문 100줄과 주변 대사 1,000줄이 들어갈 수 있습니다. 입력만으로 문맥 한도를 넘는 배치는 서버가 거부해도 같은 대사를 작은 배치로 다시 요청할 방법이 없습니다. 구현 노트의 실제 영상은 번역 대상 22줄이어서 이 경로를 다루지 않습니다.
- **제안** **(추천)** 문맥 초과가 확인되면 로컬 배치만 분할하고, 한 줄까지 줄었으면 주변 문맥을 줄여 재시도하세요. 또는 로컬 배치 크기와 주변 문맥을 처음부터 줄일 수 있습니다. 두 번째 방식은 구현이 작지만 긴 단일 대사는 여전히 한도를 넘을 수 있습니다.

### LTR-R7 UTF-8로 저장할 수 없는 번역 응답이 검증을 통과합니다

- **분류** `확실한 문제`
- **심각도** 낮음
- **위치** `make_foreign_subtitle.py:529`, `make_foreign_subtitle.py:605`, `mixed_subtitle.py:153`
- **내용** 짝이 없는 Unicode 서로게이트가 JSON 이스케이프로 들어오면 Python이 문자열로 디코딩하고, 현재 검증은 비어 있지 않은 문자열로 받아들입니다. 이후 UTF-8 캐시를 쓰다가 `UnicodeEncodeError`가 발생하며 혼합 모드는 원문 저장 단계까지 가지 못합니다. 응답 검증 통과와 인코딩 실패를 메모리에서 확인했습니다.
- **제안** 응답 검증 시 UTF-8로 인코딩할 수 없는 값을 거부하고 기존 형식 오류 재시도 경로로 보내세요.

### LTR-R8 Linux에서 실행 파일이 없을 때 macOS 설치 명령만 표시합니다

- **분류** `확실한 문제`
- **심각도** 낮음
- **위치** `make_foreign_subtitle.py:117`, `make_foreign_subtitle.py:769`, `README_LINUX.md:39`
- **내용** Linux 혼합 모드에서 `llama-server`가 없으면 원문 자막은 저장되지만 오류는 `macOS: brew install llama.cpp`만 안내합니다. FKS의 사전 검사에서는 실제로 조회한 실행 파일인 `llama-server` 대신 `local`을 찾을 수 없다고 표시합니다.
- **제안** Linux에서는 llama.cpp의 `llama-server`를 설치해 `PATH`에서 찾을 수 있게 하는 방법을 안내하고, FKS 경고에도 누락된 실행 파일명을 표시하세요.

읽기 전용 환경에서 임시 디렉터리 생성이 막혀 자체 검증 전체의 통과 여부를 재확인하지 못했습니다. 실제 모델 다운로드와 영화 재실행, Linux의 `llama-server` 구동, FKS 장편 번역의 품질과 처리 시간은 확인하지 못했습니다.
