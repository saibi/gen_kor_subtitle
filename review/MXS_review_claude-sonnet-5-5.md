# [MXS] 교차리뷰 (Claude Code)

## 요약

**종합 판단:** 계획의 핵심 흐름은 구현되어 있습니다. 구성은 시간축 보정, Silero 구간 분할, 구간별 Whisper 언어 감지, 외국어만 번역, 시작 100ms 보정, 5개 형식 출력입니다. 확실한 결함은 중간 심각도 2건입니다. 하나는 복구 불가능한 긴 작업을 한 번에 잃을 수 있는 경로입니다. 다른 하나는 디스크를 계속 쌓는 경로입니다. 가장 큰 미충족 항목은 MXS-M4입니다. 실제 영화에서의 싱크 전후 비교, 실제 번역, Linux 실측이 모두 빠져 있습니다.

이 세션에는 Bash가 없어 `test_mixed_subtitle.py`를 직접 실행하지 못했습니다. 아래 내용은 모두 코드를 읽어서 확인한 것입니다.

## 지적사항

### MXS-R1
- **분류**: 결정 필요
- **심각도**: 높음
- **위치**: `mixed_subtitle.py:49-109`, `make_subtitle.py:303-312`
- **내용**: Whisper 전사는 영화 전체를 끝까지 메모리에서 돈 뒤에야 번역하고 저장합니다. 전사 결과는 어디에도 저장되지 않습니다. 계획이 약속한 재사용은 번역 배치 캐시뿐입니다.
  - Linux CPU에서 2시간 영화는 수 시간이 걸립니다. 번역기 로그인이 만료됐거나 Ctrl-C로 중단하면, 임시 폴더가 지워지면서 전사 결과가 사라집니다.
  - 재실행하면 전사부터 다시 해야 합니다.
  - 32구간마다 `whisper-cli`가 모델을 다시 로드합니다. 계획의 "묶음당 한 번"과는 해석이 다릅니다. 1500구간이면 약 47번 로드합니다.
- **제안**:
  - (추천) 묶음마다 검증된 전사 결과를 `out_dir`의 숨김 캐시에 저장합니다. 키는 WAV 지문, 모델, 스레드, 구간 목록의 해시입니다. 재실행 시 이어서 진행합니다.
  - 번역 단계만 먼저 분리해 실패 시 전사 JSON을 보존합니다. 전사 재개는 지원하지 않습니다.
  - 현재 상태를 유지하고 README에 "중단 시 처음부터"라고 명시합니다.

### MXS-R2
- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `make_subtitle.py:352-358`
- **내용**: 기존 `.wav`가 있는 상태에서 `--keep-wav`로 실행하면, 매번 `…-aligned-XXXX.wav`를 새로 만듭니다. `reusable` 판정은 `saved_wav`만 보므로 이 대체 파일은 절대 재사용되지 않습니다. 같은 영상을 3번 돌리면 장편 WAV(약 230MB/2시간 이상)가 3개 쌓입니다.
- **제안**: 대체 파일 이름을 `{stem}.aligned.wav`처럼 결정적으로 정합니다. `reusable` 판정에서 이 경로와 해당 manifest도 확인합니다.

### MXS-R3
- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `mixed_subtitle.py:29-35`
- **내용**: 구간 검증이 엄격해서 비정상 입력 하나가 영화 전체 처리를 `ValueError`로 중단시킵니다.
  - VAD가 패딩으로 앞 구간과 겹치는 구간을 내면 `last_end <= first`가 깨집니다.
  - 마지막 구간이 `frames`로 잘리면 `first == last`가 되어 `first < last`가 깨집니다. 예를 들어 WAV 끝에서 시작하는 구간입니다.
  - 이 검증은 가장 먼저 실행됩니다. 구간 하나 때문에 전체가 실패합니다.
- **제안**: 번호와 개수 불일치만 오류로 처리합니다. `first = max(first, last_end)`로 보정하고, 길이가 0 이하인 구간은 버립니다.

### MXS-R4
- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `make_subtitle.py:245`
- **내용**: JSON 경로는 `read_text(encoding="utf-8")`를 엄격 모드로 읽습니다. 같은 파일의 SRT 경로(`errors="replace"`)와 `transcribe_mixed`(`errors="replace"`)는 방어하고 있습니다. `whisper-cli -oj`가 한글이나 일본어 토큰 경계에서 잘린 바이트를 내보내면 `UnicodeDecodeError`가 납니다. 이는 `ValueError`로 잡혀 "처리 실패"가 됩니다.
  - 인식이 모두 끝난 뒤에 실패하므로 손실이 큽니다.
  - `--formats json`을 쓰는 단일 언어 경로에만 해당합니다.
  - whisper.cpp가 실제로 잘린 바이트를 내보내는지는 이번에 확인하지 못했습니다.
- **제안**: `errors="replace"`로 읽습니다. 이후 `whisper_text`가 `\ufffd`를 제거합니다.

### MXS-R5
- **분류**: 결정 필요
- **심각도**: 중간
- **위치**: `mixed_subtitle.py:39-46`
- **내용**: `needs_translation`은 한국어로 감지된 줄에서 "소문자 로마자 단어가 2개 이상"일 때만 번역합니다. 한국어 영화에 끼는 짧은 외국어 대사가 이 기능의 대상인데, 한 단어짜리 영어("Okay.", "Sorry.", "Thank you.")는 `ko`로 오감지되면 번역되지 않습니다. 계획이 짧은 대사를 위험 요소로 적고 M4에서 점검하기로 했지만, 점검 기록이 없습니다. 테스트에도 이 사례가 없습니다.
- **제안**:
  - (추천) 한글이 전혀 없는 줄은 감지 언어와 무관하게 번역합니다. 계획의 로마자 이름·약어 제외 조건과 충돌하지 않으려면 대문자 약어와 고유명사 형태는 제외합니다.
  - 지금 규칙을 유지하고 한계를 README에 적습니다.
  - 번역 대상 판정에 `--translate-all-latin` 같은 옵션을 둡니다.

### MXS-R6
- **분류**: 결정 필요
- **심각도**: 중간
- **위치**: `test_mixed_subtitle.py` 전체, `plan/README.md`
- **내용**: 마일스톤 완료 기준에 비해 자체 검증이 비어 있는 부분이 있습니다.
  - **M1**:
    - 양의 컨테이너 시작과 음수 PTS는 구현 노트에는 확인했다고 되어 있으나 테스트에는 없습니다.
    - manifest 재사용 분기(`os.link`)가 테스트되지 않습니다.
    - `--keep-wav` 대체 파일 경로가 테스트되지 않습니다.
    - `--overwrite-audio` 경로가 테스트되지 않습니다.
  - **M2**:
    - 구간 0개일 때 `transcribe_mixed`부터 출력까지의 흐름이 테스트되지 않습니다.
    - 번역 대상이 없으면 번역기를 부르지 않는다는 점이 단언되지 않습니다.
    - 33개 이상 구간의 묶음 분할이 테스트되지 않습니다.
    - 영어 전용 모델 오류가 테스트되지 않습니다.
  - **M3**:
    - SMI 검증이 부분 문자열 하나뿐입니다.
    - `validate_subtitle_args`(`--no-vad`와 `--translator` 조합)가 테스트되지 않습니다.
  - **M4**: 영화 구간에서 보정 전후 발화 오차, 실제 번역, Linux 실측이 없습니다. 구현 노트의 사유(대상 영상과 시점이 제공되지 않음)는 합리적입니다. 다만 이는 완료가 아니라 미완 항목입니다.
- **제안**:
  - (추천) 위 M1~M3 분기는 가짜 `subprocess`나 합성 WAV로 assert 테스트를 추가합니다. 그리고 `plan/README.md`에서 M4를 "부분 완료(합성 영상만)"로 표시합니다.
  - 테스트는 추가하지 않고 M4 표시만 고칩니다.

### MXS-R7
- **분류**: 확실한 문제
- **심각도**: 낮음
- **위치**: `make_subtitle.py:316-317`
- **내용**: 계획은 "임시 결과를 모두 검증한 뒤 최종 반영"이라고 했습니다. 구현은 형식마다 `replace`를 순차 호출합니다. 중간에 예외가 나면 일부 형식만 새 결과이고 나머지는 이전 결과로 남아 시각이 어긋납니다. 같은 파일시스템이라 가능성은 낮습니다.
- **제안**: `stage.with_suffix(...)`가 모두 존재하는지 먼저 검사한 뒤 교체합니다. 이름 충돌이 우려되면 교체 순서를 SRT 마지막으로 합니다.

### MXS-R8
- **분류**: 결정 필요
- **심각도**: 낮음
- **위치**: `make_subtitle.py:306` (`prefix.name`), `make_foreign_subtitle.py:486-497`
- **내용**: 번역기 프롬프트에 영상 파일명(`Title:`)이 그대로 전달됩니다. 계획의 고지 범위("대상 대사와 주변 자막 텍스트")에는 파일명이 없습니다. 번역 캐시는 `~/.cache/gen_kor_subtitle/translations/`에 자막 텍스트를 평문으로 계속 남기며 정리 방법이 없습니다. 다국어 모델 확인도 모든 인식이 끝난 뒤에야 이루어집니다(`mixed_subtitle.py:80`). 영어 전용 모델을 지정하면 첫 묶음 이후에야 실패를 알게 됩니다.
- **제안**:
  - (추천) 번역기에는 영상 파일명 대신 빈 제목이나 고정 제목을 전달합니다. README에 캐시 위치를 적습니다.
  - 현재 동작을 유지하고 README에 고지만 추가합니다.
  - 모델 파일명이 `.en`이면 시작 전에 거부합니다.

## 검증하지 못한 것
- 테스트 스위트(`python3 -m unittest`, `test_make_foreign_subtitle.py`)를 실행하지 못했습니다. Bash가 비활성화되어 있었습니다.
- `whisper-vad-speech-segments`의 실제 출력 형식, 특히 `-vmsd`, `-t` 옵션 지원 여부와 구간 겹침 여부는 소스를 보지 않았습니다. 계획서에 적힌 Mac 실측 결과를 신뢰했습니다.
- `whisper-cli -oj`가 잘린 UTF-8 바이트를 실제로 내보내는지 확인하지 못했습니다 (R4).
- Linux 실기 동작, 실제 영화에서의 싱크 오차와 오인식률, 실제 번역기 응답 품질은 이번 리뷰에서 확인하지 않았습니다.
- `test_make_foreign_subtitle.py`, `test_make_subtitle_linux.py`가 FKS와 Linux 회귀를 충분히 덮는지는 읽지 않았습니다.
