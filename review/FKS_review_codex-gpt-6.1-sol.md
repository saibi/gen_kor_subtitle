# FKS 교차리뷰 (codex)

## 요약

**수정 후 재검토가 필요합니다.** 기본 처리 흐름은 구현됐지만, 에이전트 도구 격리, 실패 시 폴백, 다중 CD 자막, 번역 검증·캐시 복구에서 문제가 확인됐습니다.

커밋 `9919691`의 대상 파일과 재사용 함수를 읽었습니다. 기존 자체 검증은 `ok`로 통과했습니다. 추가로 네트워크·파일 저장·실제 에이전트 실행 없이 모의 검증하여 주요 실패 경로를 재현했습니다. 파일은 수정하지 않았습니다.

| 계획 | 구현 상태 |
|---|---|
| 2~3장 처리 흐름 | 기본 순서는 구현. 번역 실패 시 다음 방법을 시도하지 않는 예외가 있음 |
| 4장 번역 | 배칭·문맥·JSON 번호 검사·캐시 구현. 빈 번역문 검증과 캐시 손상 복구 부족 |
| 4장 싱크 | 길이 검사·선택 도구 호출 구현. 보정 실패 및 보정 결과의 품질 처리 부족 |
| 5장 구조 | 별도 스크립트·기존 함수 재사용·환경변수 설정·Quick Action 구현 |
| FKS-Q1~Q5 | 엔진 선택·공개 사이트·OCR 제외·출력 이름·원어 보관 구현. Q1의 도구 격리는 불충분 |
| FKS-M1 | 파서·트랙 선택 검증 있음. 실제 추출 검증 없음 |
| FKS-M2 | JSON 번호 검사 검증 있음. 번역 전후 cue 보존·재시도·재개 검증 부족 |
| FKS-M3~M6 | 기능 코드는 있으나 각 마일스톤의 완료 기준을 확인하는 자체 검증 없음 |

## 지적사항

### FKS-R1. Codex 번역 실행에서 도구 사용이 차단되지 않음

- **분류**: `확실한 문제`
- **심각도**: 높음
- **위치**: `make_foreign_subtitle.py:48`, `make_foreign_subtitle.py:54`, `README.md:129`
- **내용**: Codex에는 읽기 전용 샌드박스만 지정합니다. 사용자 설정과 연결된 MCP 도구를 차단하지 않으며, “Do not use any tools”는 프롬프트 지시뿐입니다. 읽기 전용은 파일 읽기까지 금지하지 않습니다. 외부 자막에 지시문이 삽입되고 사용자에게 외부 쓰기가 가능한 MCP가 연결된 경우, 빈 작업 폴더만으로 그 도구의 사용을 막지 못합니다. README의 “도구 사용을 끈 채 실행” 설명과도 다릅니다.
- **제안**: 번역 실행에서는 사용자 도구 설정을 상속하지 않고, MCP·앱·셸 등 도구를 명시적으로 비활성화하십시오. 엔진마다 실제 차단 가능 여부를 확인하고, 차단할 수 없는 엔진은 안전한 번역 경로로 제공하지 않아야 합니다. 자막을 비신뢰 데이터로 구분하는 프롬프트도 추가하되, 이를 격리 수단으로 대신하지 마십시오.

### FKS-R2. Quick Action이 파일명을 AppleScript 코드에 직접 삽입함

- **분류**: `확실한 문제`
- **심각도**: 높음
- **위치**: `install_quick_action.py:38`
- **내용**: `$name`을 AppleScript 문자열에 직접 넣습니다. 파일명이 `Movie" & (do shell script "id") & ".mkv`이면 이 표현식이 그대로 `osascript -e`의 소스에 들어가는 것을 확인했습니다. 일반적인 따옴표 포함 파일명도 알림 구문을 깨뜨릴 수 있습니다. 기존 코드에서 이어진 문제이며 새 외국영화 Quick Action도 동일하게 사용합니다.
- **제안**: 고정된 AppleScript의 `on run argv`로 파일명을 전달하고, 알림에서는 인수 값을 사용하십시오. 파일명을 코드 문자열에 연결하지 마십시오.

### FKS-R3. 번역기 오류가 온라인 한국어 자막 폴백까지 막음

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `make_foreign_subtitle.py:474`
- **내용**: 내장 영어 자막을 얻은 뒤 번역기가 없거나 실행에 실패하면 즉시 `False`를 반환합니다. 따라서 뒤의 온라인 단계에서 번역 없이 사용할 한국어 자막을 구할 수 있어도 검색하지 않습니다. 번역기 미설치 상황을 모의 실행하여 `online`이 호출되지 않는 것을 확인했습니다. 계획의 “실패하면 다음 방법”과 다릅니다.
- **제안**: 사용량 한도로 중단해야 하는 오류와 해당 방법만 실패한 오류를 구분하십시오. 번역기 미설치·실행 불가 등에서는 다음 방법을 시도하고, 온라인 한국어 자막 경로를 사용할 수 있게 하십시오.

### FKS-R4. 제목 검색 실패로 이미 확보한 해시 일치 후보가 사라짐

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `make_foreign_subtitle.py:277`, `make_foreign_subtitle.py:285`
- **내용**: 해시 검색 결과를 확보한 뒤에도 제목 검색을 반드시 실행합니다. 제목 검색에서 타임아웃·차단·XML 오류가 발생하면 함수 전체가 예외로 종료되어 정상적인 해시 일치 후보도 다운로드하지 않습니다. 해시 결과 성공 → 제목 검색 실패 조합으로 재현했습니다.
- **제안**: 두 검색의 오류를 독립적으로 처리하여 확보한 후보를 유지하십시오. 해시 후보를 먼저 다운로드하고, 사용할 후보가 없을 때 제목 검색으로 넘어가는 방식도 가능합니다.

### FKS-R5. 다중 CD ZIP에서 한 편의 일부만 자막으로 생성함

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `make_foreign_subtitle.py:302`
- **내용**: ZIP에 자막이 여러 개 있으면 가장 큰 파일 하나만 읽습니다. `Movie.CD1.srt`, `Movie.CD2.srt`가 들어 있는 ZIP으로 확인한 결과 CD1만 반환했습니다. 전체 영화에 첫 CD 자막만 붙여도 성공으로 종료하고, 이후에는 `.ko.srt`가 존재하므로 건너뜁니다.
- **제안**: 최소한 다중 CD 구성을 감지하여 해당 후보를 거부하고 다음 후보를 시도하십시오. CD별 길이와 오프셋을 확인하지 않은 자동 병합은 피하십시오.

### FKS-R6. 싱크 보정 실패를 성공으로 처리함

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `make_foreign_subtitle.py:322`, `make_foreign_subtitle.py:339`
- **내용**: 설치된 싱크 도구가 실패해도 원래 타이밍을 반환합니다. 호출자는 이를 정상 결과로 받아 다른 후보 검색을 중단합니다. 도구가 종료 코드 1을 반환하는 상황에서 원본 cue가 그대로 반환되는 것을 재현했습니다. 도구 성공 후에도 계획에 있는 “보정 후 일치도가 낮으면 다음 후보” 검사가 없습니다.
- **제안**: 도구 실패 시 `None`을 반환해 다음 후보를 시도하십시오. 보정 결과에도 유효한 cue·영상 범위와 도구가 제공하는 신뢰도 등을 확인하는 검증을 추가하십시오.

### FKS-R7. 빈 번역문이 검증을 통과하고 최종 cue가 삭제됨

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `make_foreign_subtitle.py:369`, `make_foreign_subtitle.py:386`, `make_subtitle.py:254`
- **내용**: 응답은 키와 문자열 타입만 검사합니다. `{"1": ""}`도 정상 번역으로 승인되는 것을 확인했습니다. 빈 문자열이나 공백·태그뿐인 번역문은 이후 정리 과정에서 빈 cue가 되고, 공통 후처리에서 빠집니다. 결과적으로 M2의 “cue 수와 타이밍 동일” 조건을 깨뜨리고 누락된 번역을 캐시합니다.
- **제안**: 모든 번역문을 정리한 뒤 비어 있지 않은지 검사하고, 실패한 묶음을 재시도하십시오. 최종 저장 전에도 입력과 출력의 cue 수·타이밍이 같은지 확인하십시오.

### FKS-R8. 캐시 쓰기 중 중단되면 이후 재개가 계속 실패함

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `make_foreign_subtitle.py:397`, `make_foreign_subtitle.py:411`
- **내용**: 캐시를 기존 파일에 직접 덮어씁니다. 긴 영화 번역 중 강제 종료나 디스크 부족이 발생하면 JSON이 잘릴 수 있습니다. 다음 실행은 이를 복구하지 않고 `json.loads`에서 실패합니다. 잘린 캐시로 `JSONDecodeError`를 재현했으며, `--force`도 같은 캐시를 사용하므로 해결되지 않습니다.
- **제안**: 같은 디렉터리의 임시 파일에 쓴 뒤 원자적으로 교체하십시오. 로드 시 JSON 구조·키·값을 검사하고, 손상된 캐시는 경고 후 제외하여 재번역할 수 있게 하십시오.

### FKS-R9. 온라인 전용 실행과 dry-run도 Whisper 설치를 요구함

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `make_foreign_subtitle.py:526`, `make_subtitle.py:58`
- **내용**: 방법 선택과 기존 자막 확인보다 먼저 `ensure_dependencies(auto_install=True)`를 실행합니다. 따라서 `--method online`으로 한국어 자막만 받거나 기존 파일 때문에 건너뛸 상황에서도 `whisper-cli`를 설치하려 합니다. `--dry-run`도 Homebrew 설치를 실행할 수 있고, Homebrew가 없으면 검색 전에 종료됩니다.
- **제안**: 실제로 실행할 단계 직전에 필요한 의존성만 확인하십시오. dry-run에서는 설치하지 말고 사용 가능 여부만 보고하십시오.

### FKS-R10. 비신뢰 다운로드의 전체 크기에 제한이 없음

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `make_foreign_subtitle.py:248`, `make_foreign_subtitle.py:301`
- **내용**: `http_get()`은 응답 전체를 제한 없이 메모리에 읽습니다. ZIP 내부 자막의 10MB 제한은 다운로드가 끝난 뒤 적용됩니다. 큰 불필요 파일이 포함된 ZIP이나 비정상 응답을 받으면 자막 크기 제한과 무관하게 메모리를 소진할 수 있습니다.
- **제안**: 응답을 청크 단위로 읽으며 실제 수신량에 상한을 두십시오. ZIP도 항목 수·허용 자막 크기를 검사하고, 상한 초과 시 해당 후보를 버리십시오. ZIP을 디스크에 풀지 않는 현재 방식은 경로 조작 방지 측면에서 유지할 만합니다.

### FKS-R11. 겹치는 자막을 SMI로 변환하면 시간 순서가 뒤집힘

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `make_foreign_subtitle.py:483`, `make_subtitle.py:283`
- **내용**: ASS 등에는 동시에 표시되는 cue가 흔합니다. `1~5초`, `3~6초` cue를 공통 변환기에 넣으면 SMI의 SYNC가 `1000 → 5000 → 3000 → 6000` 순서로 생성되는 것을 확인했습니다. 플레이어에 따라 대사가 사라지거나 표시 시점이 잘못될 수 있습니다. 기존 음성인식용 변환기를 재사용하면서 새 입력 범위에 필요한 처리가 빠졌습니다.
- **제안**: SMI는 시작·종료 이벤트를 시간순으로 처리하고, 각 시점의 활성 대사를 함께 출력하십시오. SRT의 원래 cue와 타이밍은 유지하십시오.

### FKS-R12. 계획의 검색·번역 세부 조건이 일부 미반영됨

- **분류**: `결정 필요`

### FKS-R13. M2~M6의 완료 조건을 확인할 회귀 검증이 부족함

- **분류**: `확실한 문제`
- **심각도**: 낮음
- **위치**: `test_make_foreign_subtitle.py:6`, `test_make_foreign_subtitle.py:32`, `test_make_foreign_subtitle.py:35`
- **내용**: 현재 검증은 파서·이름 해석·JSON 키·트랙 선택에 집중되어 있습니다. 배치 경계·재시도·캐시 재개·검색 실패·다중 파일 ZIP·싱크 실패·전체 폴백·Quick Action 인수 전달은 검사하지 않습니다. 위의 재현 가능한 결함들도 기존 검증은 모두 통과합니다. “각 마일스톤마다 작은 자체 검증”이라는 계획에 미달합니다.
- **제안**: 실제 네트워크나 모델 호출 대신 모의 응답으로 위 실패 경로의 회귀 검증을 추가하십시오. 정상 경로에는 100개를 넘는 cue의 개수·타이밍 보존과 CP949 SMI 전체 파싱을 포함하십시오.
