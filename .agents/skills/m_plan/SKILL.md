# m_plan — 요청을 계획 문서로

구현은 하지 않는다. 다른 에이전트가 그대로 따라 구현할 수 있을 만큼 구체적인 계획을 만드는 것이 목표다.

## 입력
- 스킬과 함께 받은 인수가 **존재하는 파일 경로**면 그 파일 내용이 요청이다. 아니면 인수 전체(여러 줄 포함)가 요청이다.
- 인수가 비어 있으면 무엇을 개발하고 싶은지 묻는다.

## 절차
1. **파악**: 요청을 읽고, 관련된 기존 코드·문서(`AGENTS.md`, `plan/README.md`, 재사용할 만한 코드)를 확인한다.
2. **ID 정하기**: 계획 내용을 가장 잘 나타내는 영문 대문자 3자 약어 (예: `FKS` = Foreign film Korean Subtitle). `plan/README.md`에서 중복을 확인한다.
3. **전제 검증**: 계획이 기대는 불확실한 기술 전제는 짧은 실험으로 확인한다 (CLI 옵션 존재 여부, 외부 사이트·API 접근 가능 여부, 응답 시간 등). 확인 결과와 날짜를 계획에 적는다. 추측으로 계획하지 않는다.
4. **작성**: 아래 템플릿으로 `plan/<ID>_plan_<에이전트>-<모델>.md`를 만들고 (작성자 표기는 `AGENTS.md`), `plan/README.md` 인덱스 표에 `| <ID> | <계획 이름> | 계획 중 |` 행을 추가한다.
5. **결정 확정**: 결정이 필요한 사항을 `<ID>-Q1`, `<ID>-Q2`…로 적고 사용자에게 **한 번에 하나씩** 묻는다.
   - 각 질문에 선택지 2~3개를 주고, 추천안에 `(추천)`과 이유를 붙인다.
   - 사용자가 선택지에 없는 답을 하면 실현 가능한지 실험으로 확인한 뒤 결과를 알려주고 반영한다.
   - 답을 받으면 `✅`로 확정 표시하고, 본문의 관련 부분도 그 결정에 맞게 고친다.
6. **마무리**: 모든 결정이 확정되면 인덱스 상태를 `계획 확정 (구현 전)`으로 바꾸고, 커밋할지 묻는다. 다음 단계는 `/m_impl <ID>`라고 안내한다.

## 템플릿 (`plan/<ID>_plan_<에이전트>-<모델>.md`)
```markdown
# [<ID>] <계획 이름>

## 1. 목표
<무엇을, 왜. 범위 밖인 것도 명시>

## 2. 전체 흐름
<처리 순서·우선순위. 필요하면 다이어그램>

## 3. 단계별 상세
### 1) <단계>
- <구체적인 방법, 사용할 명령/API/형식, 실패 시 동작>

## 4. 공통 모듈
<여러 단계가 공유하는 부분: 입출력 형식, 외부 도구 호출, 캐시, 오류 처리>

## 5. 구현 구조
- 파일 구성, 재사용할 기존 코드, 의존성 원칙, 설정 방법
- CLI/사용법 초안

## 6. 결정 사항
- **<ID>-Q1** <질문> — 선택지 … (확정되면 `✅ <결정 내용>`)

## 7. 마일스톤
| # | 내용 | 완료 기준 |
| :--- | :--- | :--- |
| <ID>-M1 | … | <검증 가능한 기준> |
```
