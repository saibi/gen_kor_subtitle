# m_impl — 계획대로 구현하고 기록하기

## 입력
- `<ID>`: 구현할 계획 ID. `plan/<ID>_plan_*.md`가 없으면 `/m_plan`을 먼저 하라고 안내하고 멈춘다.
- `--review <에이전트> [모델]`: 구현을 마친 뒤 `m_review` 스킬의 절차를 이어서 수행한다.

## 절차
1. **계획 확인**: `plan/<ID>_plan_*.md`와 `AGENTS.md`를 읽는다. 계획 문서를 수정하게 되면 `AGENTS.md`의 작성자 표기 규칙대로 변경 기록을 남긴다. 확정(`✅`)되지 않은 결정 사항이 있으면 구현 전에 m_plan 방식(선택지 + 추천안, 하나씩)으로 묻는다.
2. **구현 노트 시작**: 아래 템플릿으로 `impl/<ID>_impl_<에이전트>-<모델>.md`를 만들고 (이미 다른 에이전트의 노트가 있으면 새로 만들지 말고 그 파일에 변경 기록을 남기며 이어서 쓴다) 아키텍처 초안을 적는다.
3. **마일스톤 순서로 구현**: 각 마일스톤을 마칠 때마다
   - 작은 자체 검증을 남긴다 (`test_*.py`의 assert 기반 검사, 또는 실제 실행). 외부 서비스·CLI 연동은 실제 실행으로 최소 1회 확인한다.
   - 구현 노트의 `진행 기록`에 핵심만 1~3줄 적는다 (무엇을 했고 어떻게 확인했는지). 사소한 수정은 적지 않는다.
4. **마무리**:
   - 구현 노트의 `계획 대비 변경`에 계획과 달라진 점마다 **상황**과 **근본 이유**를 적는다. `검증 결과`와 `남은 한계`도 채운다.
   - 계획 문서에도 반영한다 (보류·변경 표시). `plan/README.md` 상태를 `구현 완료`로 바꾼다.
   - README 등 사용자 문서를 갱신한다.
   - 커밋한다 (메시지 규칙은 `AGENTS.md`). 리뷰가 이 커밋을 기준으로 하므로 커밋 해시를 구현 노트에 적는다.
5. **`--review`가 있으면** `.agents/skills/m_review/SKILL.md`를 읽고 그 절차를 그대로 수행한다.

## 템플릿 (`impl/<ID>_impl_<에이전트>-<모델>.md`)
```markdown
# [<ID>] 구현 노트

- 계획: plan/<ID>_plan_<에이전트>-<모델>.md
- 구현 커밋: <해시> (리뷰 반영 커밋은 review/<ID>_refine_*.md)

## 아키텍처
<파일 구성, 주요 모듈/함수의 역할, 데이터 흐름. 다이어그램이나 표로 간결하게>

## 핵심 설계 결정
- <결정> — <이유>

## 진행 기록
- <ID>-M1: <무엇을 했고 어떻게 확인했는지>

## 계획 대비 변경
| 항목 | 계획 | 최종 구현 | 상황과 근본 이유 |
| :--- | :--- | :--- | :--- |

## 검증 결과
<자체 검증, 실제 실행으로 확인한 것과 확인하지 못한 것>

## 남은 한계
- <알려진 한계와 개선 방향>
```
