# [MXS] 한국영화 혼합 언어 자막 및 싱크 개선

## 1. 목표

- 한국어 중심 영상에서 한국어, 영어, 일본어 등 여러 언어의 대사를 구간별로 인식한다. 한국어 인식문을 유지하고 외국어 대사를 한국어로 번역해 같은 자막에 시간순으로 넣는다.
- 영상 재생 시간축에 대사 시각을 맞추고, 보정된 자막 시작만 기본 100ms 앞당긴다. 종료 시각은 기존 표시 시간 보정 규칙을 따른다.
- macOS와 Linux 자막 생성기에 적용한다. 입력은 기존 FFmpeg 오디오 선택 규칙을 따르는 한 트랙이다.

## 2. 전체 흐름

영상 시간축에 맞춘 WAV 추출 → Silero 음성 구간 탐지 → 구간별 Whisper 언어 감지·원어 전사 → 외국어 부분만 번역 → 영상 시간축에 배치 → 표시 시작 100ms 당김 → 지정 형식 저장.

기본 실행과 `--lang ko`는 기존 한국어 인식 경로를 사용한다. `--lang mixed`에서 구간별 언어 감지와 외국어 번역을 자동으로 진행한다. 두 경로 모두 같은 WAV 시간축 보정과 표시 시작 처리를 적용한다.

## 3. 단계별 상세

### 1) 영상과 WAV 시간축 맞추기

- macOS와 Linux의 오디오 추출에서 FFmpeg `-af aresample=async=1:first_pts=0` 후보를 적용한다. 영상보다 늦게 시작하는 첫 오디오와 타임스탬프가 끊기는 구간을 합성 입력으로 확인하고, 양의 컨테이너 시작점과 음수 PTS에서도 플레이어의 재생 0점 기준인지 확인한다.
- Linux `--start`/`--duration` 자막은 기존대로 잘라낸 샘플의 0점 기준이다. 별도로 영상 시작 시각을 더하면 이중 보정이 된다.
- macOS에서 기존 WAV를 재사용할 때는 같은 원본의 보정된 추출 파일인지 확인한다. 보정 여부가 확인되지 않는 WAV가 있으면 임시 경로에 새로 추출하고 기존 WAV를 보존한다. `--keep-wav`는 정렬된 WAV를 보관하고, `--overwrite-audio`가 명시되면 재추출한다.
- 싱크 재현 시 첫 대사·중간·끝의 실제 발화 시작을 표시해 인식 자막과 비교한다. 전체가 같은 양만큼 어긋나면 추출 기준점을 점검하고, 뒤쪽으로 갈수록 커지면 오디오 PTS와 구간 오프셋 누적을 점검한다. 개별 대사의 어긋남은 VAD 경계와 Whisper 시작·종료를 각각 비교한다.

### 2) 음성 구간별 언어 감지와 원어 전사

- 혼합 언어 모드에서 `whisper-vad-speech-segments -f <wav> -vm <model>`로 Silero 구간을 가져온다. stdout의 1/100초 값을 밀리초로 변환하고, WAV 샘플 범위로 제한한 뒤 표준 라이브러리 `wave`로 원래 순서대로 구간을 자른다. 구간 번호·개수·숫자 범위를 검증하고, 정상적인 무음 결과와 실행·파싱 실패를 구분한다.
- `whisper-cli -l auto -oj`에 여러 `-f <clip> -of <prefix>` 쌍을 넣어 모델 로드를 묶음당 한 번으로 제한한다. 임시 파일 수와 명령 길이를 제한하는 유한한 묶음으로 실행한다. Linux의 `-ng`와 각 플랫폼의 스레드 설정을 유지한다.
- JSON의 `result.language`와 각 대사의 `offsets.from/to`를 읽는다. 대사별 시작·종료에 잘라낸 실제 WAV 시작 오프셋을 더하고 구간 경계 밖의 시각을 자른다. 위치는 항상 원본 WAV의 샘플 위치로 계산한다.
- 대사 구간 안에서 언어를 바꾸는 경우를 위해 한국어로 감지된 줄이라도 외국어 문장이 뚜렷이 남으면 번역 대상으로 삼는다. 한국어 문장 속 로마자 이름·약어만으로 번역을 요청하지 않는다. 매우 짧은 대사, 쉼 없이 바뀌는 언어, 겹쳐 말하는 대사는 실제 영상에서 인식률을 점검한다.
- 혼합 언어 모드와 `--no-vad`를 함께 지정하면 CLI에서 조합을 안내한다. VAD 실행 파일이나 다국어 모델을 사용할 수 없으면 원인을 알려준다. 정상적으로 인식한 구간 중 외국어가 없으면 번역기를 호출하지 않는다.

### 3) 외국어 대사만 한국어로 번역하기

- `make_foreign_subtitle.py`의 FKS 번역기 선택, 프롬프트 보호, 배치, 응답 검증과 재시도 방식을 재사용한다. 외국어 대사 ID만 번역 입력에 넣고 앞뒤 한국어 대사를 참고 문맥으로 쓴다. 한 줄에 언어가 섞이면 외국어 부분의 뜻을 반영하되 이미 한국어인 부분을 유지하도록 요청한다.
- 응답 ID와 비어 있지 않은 문자열을 검증하고, 텍스트만 같은 대사 ID에 덮어쓴다. 문맥이 달라질 수 있으므로 이 모드의 번역 캐시에는 번역 대상과 실제 전달한 문맥을 포함하고 동시 실행에도 임시 파일을 공유하지 않는다.
- 온라인 번역기를 사용하는 경우 대상 대사와 주변 자막 텍스트가 선택한 서비스에 전달된다. 오디오 파일은 로컬에서 처리한다. 번역 실패 시 오류를 표시하고 기존 완성본을 보존한다. 재실행은 검증을 통과한 번역 배치를 재사용한다.

### 4) 표시 시작 시각 보정과 출력

- Whisper 결과의 시각을 영상 또는 샘플 시간축으로 복원한 뒤, 유효한 대사마다 `max(0, start_ms - 100)`을 한 번 적용한다. 0ms 근처에서 시작해도 자막이 사라지지 않으며, 종료 시각은 100ms 당김의 영향을 받지 않는다. 기존 `--max-duration` 보정은 당기기 전 시작·종료에 적용한다.
- SRT·SMI·VTT·JSON은 같은 정규화된 대사로 출력한다. TXT는 같은 텍스트 순서를 따른다. 단일 언어 JSON은 기존 구조와 메타데이터를 보존하고 대사 시각 표현을 함께 갱신한다. 혼합 언어 JSON은 대사별 원어를 기록한다.
- 잇따르는 대사는 100ms 당김 때문에 겹칠 수 있다. 겹치는 대사를 모두 유지하고, SMI에는 FKS의 시간순 이벤트 작성 방식을 재사용한다. 임시 결과를 모두 검증한 뒤 최종 출력 경로에 반영한다.

## 4. 공통 모듈

- 기존 밀리초 타임코드 변환과 FKS 자막 작성·번역 로직을 재사용한다. 두 생성기의 진입점에서 혼합 언어 처리와 표시 보정을 공통으로 호출하고, FKS의 내장·온라인 자막 및 기존 번역 호출 동작을 회귀 검증한다.
- 도구는 인자 배열로 실행하고 모델·영상 경로를 그대로 전달한다. 외부 대사 및 번역 응답은 데이터로만 다루고 파일 형식·대사 ID·시간 범위를 검사한다.

## 5. 구현 구조

- `make_subtitle.py`, `make_subtitle_linux.py`의 일반 영상 처리 경로에 연결한다. 필요할 경우 두 진입점과 FKS가 공유하는 기존 번역·출력 함수를 순환 import 없이 가져올 수 있는 파일로 옮긴다. Python 표준 라이브러리만 사용한다.
- Linux `setup_linux.sh`는 현재 고정 리비전에 있는 `whisper-vad-speech-segments` 타깃을 `whisper-cli`와 함께 빌드한다. macOS는 Homebrew 설치에 포함된 실행 파일을 사용한다. 기존 단일 언어 모드에서는 추가 VAD 실행 파일을 요구하지 않는다.
- CLI는 `./make_subtitle.py movie.mkv --lang mixed` 및 `python3 make_subtitle_linux.py movie.mkv --lang mixed`다. 혼합 모드에서 `--translator`로 FKS가 지원하는 번역기를 선택하며, 생략하면 기존 FKS 번역기 설정을 따른다.

### 전제 검증 (2026-11-21)

- macOS Homebrew의 `whisper.cpp 1.9.5_2`에 두 CLI가 들어 있고 Linux 고정 리비전에도 VAD 실행 파일의 CMake 타깃이 있다. 로컬 Silero 6.2.0은 한국어·영어·일본어 음성과 2초 간격을 넣은 15초 합성 WAV에서 세 구간을 반환했다. 첫 구간의 stdout `99.00–473.00`은 VAD 로그의 `0.99–4.73초`였다. [VAD 타깃](https://github.com/ggml-org/whisper.cpp/blob/727d3e7666485e12450746b523bfb4e7f057cc5e/examples/vad-speech-segments/CMakeLists.txt)
- 같은 혼합 WAV를 `-l auto`로 한 번에 처리하니 결과 언어는 `ko`였고, 영어는 원문이 나왔으며 일본어는 한글 음차로 나왔다. 전체 파일 하나에서 언어를 한 번 결정하는 방식으로는 이러한 오류를 복구하기 어렵다. [Whisper CLI 소스](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/examples/cli/cli.cpp)
- 같은 세 대사의 개별 WAV를 한 Whisper CLI 호출에 전달하니 JSON 세 개에서 각각 `ko`, `en`, `ja`와 해당 언어의 원문이 나왔다. 이 Mac에서 CPU 4스레드로 전체 WAV 인식은 약 30초, 개별 WAV 세 개를 묶어서 처리하는 데는 약 63초가 걸렸다.
- 합성 WAV를 실제 Silero 경계로 자른 뒤 Mac의 Metal 경로에서 세 구간을 묶어서 인식해도 세 언어와 원문을 정확히 얻었다. 모델 로드와 인식을 합친 Whisper CLI 경과 시간은 약 3.5초였다.
- 오디오가 영상보다 1.25초 늦는 합성 MKV에서 기본 추출은 신호를 WAV의 0초로 옮겼고, 후보 필터는 1.250초에 유지했다. 0.5초부터 잘라내면 샘플의 약 0.750초에 신호가 나왔다. [FFmpeg 리샘플러 문서](https://ffmpeg.org/ffmpeg-resampler.html)
- 4초짜리 오디오에서 약 1초 분량의 패킷을 중간에서 제거한 MKV는 기본 추출에서 약 3초로 줄었고, 후보 필터는 공백을 무음으로 보존해 약 4초 길이를 유지했다.

## 6. 결정 사항

- **MXS-Q1** ✅ `--lang mixed`를 명시하면 혼합 언어 인식과 외국어 번역을 자동으로 진행한다. 기존 기본 실행은 한국어 인식을 사용한다.

| MXS-M4 | 영화 샘플 확인 | 사용 가능한 로컬 영상에서 한국어 사이에 들어간 짧은 외국어 대사와 싱크가 어긋났던 구간을 확인한다. 보정 전후의 발화 기준 오차와 처리 시간, 남은 오인식 사례를 기록한다. |

**MXS-M4 부분 검증.** 합성 영상은 실제 Claude 번역과 다섯 출력 형식까지 검증했다. 로컬 영화 구간에서는 전사와 시작 시각 보정을 확인하고 번역에는 대역을 사용했다. 사용자가 싱크 불일치를 겪은 특정 영상·시각은 제공되지 않아, 발화 기준 오차는 시점을 알고 있는 합성 영상으로 검증했다.

교차리뷰 반영 후 50ms 공백을 보존하고, Silero가 긴 발화를 합칠 경우에도 25초 이내로 나눈다. 영상 파일명은 혼합 모드의 번역 요청에서 제외한다.
