# [MXS] 구현 노트

- 계획은 `plan/MXS_plan_codex-gpt-6.2-sol.md`를 참조한다.
- 구현 커밋 `61fb656`

## 아키텍처

두 자막 생성기는 공통 오디오 추출과 자막 출력을 사용한다. 혼합 언어 모드에서는 Silero가 분리한 음성을 Whisper가 구간별로 인식하고 FKS 번역기가 외국어 대사를 번역한다.

## 핵심 설계 결정

- 재생 시간축은 FFmpeg에서 WAV로 옮기고 자막의 100ms 시작 보정은 출력 직전에 적용한다.

## 진행 기록

- MXS-M1. 공유 FFmpeg 필터로 시작 지연과 중간 PTS 공백을 보존했다. 합성 MKV에 Linux 구간 추출을 적용해 0점 기준을 검증하고, macOS의 기존 WAV도 보호했다.
- MXS-M2. Silero 구간을 Whisper 묶음으로 전사하고 번역할 부분만 FKS에 전달했다. 실패 후 번역 캐시 재사용을 테스트하고, 한국어·영어·일본어 합성 영상의 실제 Claude 번역을 확인했다.
- MXS-M3. 다섯 포맷을 같은 대사에서 생성하고, 100ms 시작 이동, 0ms 하한, 겹침, 번역 실패 시 기존 결과 보존을 테스트했다.
- MXS-M4. 로컬 장편의 22초 구간 네 곳을 검사했다. 대사가 잡힌 한 구간에서 10개 대사의 시작 이동을 확인했고 전사에 약 8.9초가 걸렸다. 자막 텍스트를 보내지 않는 번역 대역을 이용했다.

## 검증 결과

- `python3 -m unittest -q`, `python3 test_make_foreign_subtitle.py`, `bash -n setup_linux.sh`를 통과했다.
- 오디오가 영상보다 1.25초 늦게 시작하고 중간에 1초가 비는 MKV에서 추출 WAV의 신호 전환이 예상 시각 20ms 이내에 있었다. 양의 컨테이너 시작과 오디오 음수 타임스탬프도 합성 MKV에서 확인했다.
- 합성 세 언어 MKV로 macOS의 실제 Whisper, Silero, Claude와 다섯 형식을 검증했다. 첫 SRT 시작은 1.120초였다. 실제 Claude 호출에는 합성 대사만 사용했다.
- Linux 진입점을 macOS의 CPU 경로에서 실제 Whisper로 실행해 세 형식과 벤치마크 JSON을 확인했다.

## 남은 한계

- 짧거나 쉼 없이 언어가 바뀌는 대사의 원어 인식은 모델에 의존한다. 로컬 영화 샘플에서도 가능성이 낮아 보이는 언어 표기가 관찰됐으며 원어별 정답은 확인하지 않았다.
- Linux 고정 리비전의 빌드 타깃을 소스에서 확인했다. Linux 장비에서 혼합 언어 모드를 실측하는 작업은 남았다.
- 번역 배치는 재사용된다. 중단된 음성 인식은 다음 실행에서 처음부터 수행한다.
